# 서준엄마네 모바일 허브 페이지

택배 전단지의 QR코드로 들어오는 서준엄마네 상품 소개 페이지입니다.
이 페이지에서는 구매하지 않고, 상품·카테고리를 누르면 네이버 스마트스토어로 이동합니다.

- 공개 주소: https://rlgus1520-boop.github.io/seojunmom/
- 상품 관리 시트: [서준엄마네 웹사이트](https://docs.google.com/spreadsheets/d/1Hbdjt6nM1cRTJX05f6y8P49eu7UCAYtAJ-eBpnRJM1w/edit)
- 직원용 안내 문서: [서준엄마네 상품 관리 안내](https://claude.ai/code/artifact/32b9d943-081e-496c-8c87-714881c6cd08)

## 어떻게 움직이나요

| 하는 일 | 어디서 | 반영까지 |
|---|---|---|
| 상품·가격·할인·이미지·구매 링크·노출·순서 | 구글 시트 "상품" 탭 | 저장 후 약 5분 |
| 카테고리 버튼 | 구글 시트 "카테고리" 탭 | 저장 후 약 5분 |
| 배너 글씨, 사진 바뀌는 간격 | 구글 시트 "배너 문구" 탭 | 저장 후 약 5분 |
| 배너 사진 (추가·순서·숨김) | 구글 시트 "배너 사진" 탭 | 저장 후 약 5분 |
| 검증 현장 사진·설명 (추가·순서·숨김) | 구글 시트 "검증 현장" 탭 | 저장 후 약 5분 |
| 클릭 수 확인 | 구글 시트 "클릭 집계" 탭 | 클릭 후 1분 안 |
| 고객센터, 스토어 주소, 디자인 | 이 저장소의 파일 → **배포** 필요 | 배포 후 1~2분 |

사이트는 열릴 때마다 시트의 "웹에 게시" 주소에서 상품, 카테고리, 배너, 검증 현장을 읽습니다.
그래서 **평소 관리는 시트만 고치면 되고, 배포가 필요 없습니다.**
어느 탭을 못 읽으면 그 부분만 `data.js` 의 비상용 내용으로 보여 줍니다.
시트 사용법은 직원용 안내 문서에 있습니다.

## 파일 구성

| 파일 | 역할 | 고칠 일 |
|---|---|---|
| `index.html` | 화면 디자인과 그리기 | 디자인 바꿀 때 |
| `data.js` | 시트 주소, 클릭 기록기 주소, 고객센터, 스토어 주소, 비상용 상품·카테고리·배너·검증 현장 | 가끔 |
| `js/sheet.js` | 시트 5개 탭을 읽고, 잘못된 값을 걸러 내고, 할인 기간·노출·순서를 계산 | 드묾 |
| `js/track.js` | 클릭 기록 보내기, 스마트스토어 링크에 네이버 유입 표시 붙이기 | 드묾 |
| `apps-script/click-log.gs` | 시트에 클릭을 적는 앱스 스크립트 원본 | 드묾 |
| `tests/sheet-test.js` | 자동 시험 61개 | 코드를 바꿀 때마다 실행 |
| `assets/` | 로고, 서체, 배너·현장·상품·아이콘 사진 | 사진 교체 시 |
| `qr/` | 인쇄용 QR코드 (손님용 주소) | 주소가 바뀔 때만 |
| `.env.example` | 비밀 키 적는 법 예시. 지금은 비밀 키가 필요 없음 | 없음 |

비밀 키나 비밀번호가 필요한 기능을 나중에 붙이면 `.env` 파일에 적습니다.
`.env` 는 `.gitignore` 에 들어 있어서 GitHub에 올라가지 않습니다.
시트 게시 주소와 클릭 기록기 주소는 원래 공개되는 주소라 `data.js` 에 적어도 됩니다.

## 배포하는 방법

배포 = 이 폴더의 파일 변경을 GitHub에 올려서 공개 사이트에 반영하는 일입니다.
시트만 고쳤다면 배포할 필요가 없습니다.

**가장 쉬운 방법**: Claude Code 대화창에 "서준엄마네 배너 문구 바꾸고 배포해줘"처럼 요청합니다.

**직접 하는 방법**: VS Code에서 **터미널 > 새 터미널** 을 열고 한 줄씩 입력합니다.

```bash
cd ~/Desktop/g/seojunmom-web
node tests/sheet-test.js          # 1. 자동 시험. 마지막 줄이 "모두 통과"여야 합니다
git add -A                        # 2. 바뀐 파일을 모두 담기
git commit -m "배너 문구 수정"      # 3. 무엇을 바꿨는지 한 줄로 저장
git push                          # 4. GitHub에 올리기 = 배포
```

1~2분 뒤 점검용 주소를 새로고침해서 확인합니다.
시험에서 "실패"가 나오면 배포하지 말고 원인을 먼저 고칩니다.

**큰 작업 전에는 이름표(태그)를 붙여 두세요.** 나중에 그 시점으로 바로 돌아갈 수 있습니다.

```bash
git tag -a before-banner -m "배너 교체 전"
git push origin before-banner
```

## 문제가 생겼을 때 되돌리는 방법

먼저 무엇이 문제인지 나눕니다.

| 상황 | 되돌리는 곳 |
|---|---|
| 상품·가격·할인이 이상함 | 구글 시트 → **파일 > 버전 기록 > 버전 기록 보기** 에서 이전 버전 복원. 5분 뒤 사이트도 돌아감 |
| 배포 후 화면이 깨지거나 기능이 이상함 | 아래 "사이트 코드 되돌리기" |
| 클릭이 기록되지 않음 | 아래 "클릭 기록기" 항목 |

### 사이트 코드 되돌리기

**방법 1. 마지막 배포 하나만 취소 (가장 안전)**

```bash
cd ~/Desktop/g/seojunmom-web
git log --oneline -5              # 최근 배포 5개 보기. 맨 위가 가장 최근
git revert HEAD --no-edit         # 맨 위 배포를 취소하는 새 기록 만들기
git push                          # 반영
```

`git revert` 는 기록을 지우지 않고 "취소" 기록을 하나 더 쌓습니다. 실수해도 다시 되돌릴 수 있습니다.
특정 배포를 취소하려면 `HEAD` 대신 `git log` 에 나온 7자리 번호를 넣습니다.

**방법 2. 이름표 시점으로 통째로 돌아가기 (주의)**

```bash
cd ~/Desktop/g/seojunmom-web
git reset --hard step3-rules      # 이름표 시점으로 파일을 모두 되돌림
git push --force                  # 공개 사이트도 그 시점으로
```

그 시점 이후의 변경이 모두 사라지니, 방법 1로 안 될 때만 씁니다.

| 이름표 | 그 시점 상태 |
|---|---|
| `before-backend` | 구글 시트 연결 전. 상품을 `data.js` 에서만 관리 |
| `step1-sheet` | 시트만 만들고 사이트는 아직 `data.js` 사용 |
| `step2-connect` | 사이트가 시트를 읽음 (할인 기간·노출·순서 반영 전) |
| `step3-rules` | 할인 기간·노출·순서까지 반영 (클릭 기록 전) |
| `step4-clicks` | 클릭 기록·네이버 유입 표시까지 반영 |
| `step5-docs` | 안내 문서와 이 README까지 정리 |
| `step6-hero-gallery` | 배너 문구·사진, 검증 현장도 시트에서 관리 (현재 구성) |

이름표 목록은 `git tag -n` 으로 볼 수 있습니다.

### 클릭 기록기

- 기록만 멈추려면 `data.js` 의 `clickLog` 를 `""` 로 바꾸고 배포합니다.
- 기록이 안 되면 `clickLog` 주소를 브라우저로 열어 "작동 중입니다" 문구가 나오는지 봅니다.
  안 나오면 시트의 **확장 프로그램 > Apps Script > 배포 > 배포 관리** 에서 웹 앱이 살아 있는지 확인합니다.
- 앱스 스크립트를 잘못 고쳤다면 **배포 관리 > 연필 > 버전** 에서 이전 버전을 고르고 배포합니다.

### 자주 생기는 문제

| 증상 | 원인과 해결 |
|---|---|
| 점검 화면에 "비상용 데이터" | 시트를 못 읽는 중. 시트 제목줄·탭 이름이 바뀌었거나 웹 게시가 해제됨. 시트 버전 기록으로 복원하거나 웹 게시를 다시 켬 |
| 점검 화면에 "비상용 데이터를 쓰는 탭: 배너 문구…" | 그 탭이 웹 게시 대상에서 빠짐. 웹에 게시 설정에서 그 탭을 다시 고름 |
| 시트를 고쳤는데 5분이 지나도 그대로 | 휴대폰이 예전 데이터를 들고 있음. 브라우저를 완전히 닫았다 열기 |
| 사진 대신 로고 | 이미지 주소가 틀렸거나 `http://` 로 시작함. `https://` 주소를 넣기 |
| 상품 칸 높이·버튼 위치가 어긋남 | 디자인 코드 문제. 마지막 배포를 되돌리기 |

## 처음 설치 기록

새 시트나 새 계정으로 옮길 때 다시 해야 하는 일입니다.

### 시트 웹 게시

1. 시트에서 **파일 > 공유 > 웹에 게시** 를 엽니다.
2. "게시된 콘텐츠 및 설정"에서 **상품, 카테고리, 배너 문구, 배너 사진, 검증 현장** 다섯 탭을 고르고, "변경사항이 있으면 자동으로 다시 게시"를 켭니다.
3. 링크 탭에서 탭별로 **쉼표로 구분된 값(.csv)** 주소를 만들어 `data.js` 의 `sheet` 안 다섯 칸(products, categories, bannerText, banner, gallery)에 넣습니다.
   주소는 끝의 `gid=` 숫자만 탭마다 다릅니다. 상품 0, 카테고리 1, 배너 사진 5, 배너 문구 6, 검증 현장 7.

### 클릭 기록기 설치

사이트에서 누른 상품·카테고리를 시트 '클릭 기록' 탭에 쌓고, '클릭 집계' 탭에서 개수를 봅니다.
손님 개인정보는 저장하지 않습니다. 시간, 종류, 이름, 이동한 주소만 저장합니다.

1. 시트 메뉴에서 **확장 프로그램 > Apps Script** 를 누릅니다.
2. `Code.gs` 내용을 모두 지우고 `apps-script/click-log.gs` 내용을 붙여 넣은 뒤 저장합니다.
   - 내용 보기: https://raw.githubusercontent.com/rlgus1520-boop/seojunmom/main/apps-script/click-log.gs
3. **배포 > 새 배포 > 웹 앱** 을 고르고, 실행은 **나**, 액세스는 **모든 사용자** 로 배포합니다.
4. 권한 창에서 **액세스 승인** 후, "확인하지 않은 앱" 경고가 나오면 **고급 > 이동 > 허용** 을 누릅니다.
5. 웹 앱 URL(`.../exec`)을 `data.js` 의 `clickLog` 에 넣고 배포합니다.

코드를 고친 뒤에는 **배포 관리 > 연필 > 새 버전** 으로 다시 배포합니다. "새 배포"를 다시 하면 주소가 바뀝니다.

### 네이버 유입 표시

스마트스토어로 가는 링크 끝에 `nt_source=seojunmom_web&nt_medium=flyer_qr` 가 자동으로 붙습니다.
스마트스토어센터 **통계 > 마케팅분석 > 사용자정의채널** 에서 이 페이지를 거친 방문·주문을 볼 수 있습니다.
끄려면 `data.js` 의 `naverChannel.source` 를 `""` 로 바꿉니다.

## 디자인 규칙

- 서체는 Pretendard, 자간 -20. 메인 색은 Warm Tangerine `#FF850D`.
- 로고는 흰 배경 위에만 놓고 그림자·테두리를 넣지 않습니다.
- 같은 줄 상품 카드의 가격과 구매 버튼은 카드 바닥에 맞춰져 있습니다. 상품명이 길어져도 버튼 높이는 같습니다.
- QR코드는 손님용 주소가 바뀌지 않는 한 다시 만들 필요가 없습니다.
